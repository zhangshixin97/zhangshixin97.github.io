## 一、本周概览

**一句话：酒旅垂直 Skill 在 GitHub 上几乎仍是荒漠，但这周冒出来一个值得立刻跟进的酒店技能库；GEO 方向则明显在爆发。**

- **OTA / 酒店民宿方向**：直接关键词（携程、美团、飞猪、酒店、民宿、OTA）搜出的 Skill 类仓库约等于零——唯一的重磅发现是 `workloom-hotel`，一个 Apache-2.0 的酒店经营系统，内置 25 个酒店官方技能（OTA 运营、差评危机、定价矩阵、收益管理、晨报、客服），恰好补齐世鑫 Skill 社区在「点评管理、定价收益、智能客服」三块空白。
- **新媒体方向**：小红书自动化 Skill 继续内卷，出现两个高质量仓库（3393★ 的 XiaohongshuSkills 和工程化程度更高的 xiaohongshu-skill），功能从「采集」扩展到「发布 + 评论互动 + 数据看板」，与现有上架的采集/视觉类正好互补。公众号方向整体与已上架 5 个 skill 重叠度高。
- **GEO / AI 搜索占位方向**：本周最热闹的赛道，扫到 15+ 个相关仓库（geo-score、su-multi-geo、gnw-marketing-prompts、ai-search-visibility-kit 等）。世鑫网站有 GEO 服务线但社区里还没有一个 GEO Skill，是明确的补位机会。注意：多数 GEO 仓库面向海外引擎（ChatGPT/Perplexity/Gemini），直接照搬到国内（豆包/DeepSeek/元宝）需要本土化改写。

**解决什么痛点**：民宿/酒店小红书账号的「发、评、看数」全链路自动化——自动图文/视频发布、按条件回复评论、点赞收藏互动、抓取笔记曝光/观看/点赞数据导出 CSV。

**风险与限制**：README 自己明示了平台风控/封号风险，必须人工复核后发布；目前主要在 Windows 上测试过。上架文案里要把「风控提示」写在最前面。

| 项 | 内容 |
|---|---|

| Stars | 0（2026-08-29 新建） |
| 协议 | MIT ✅ |

**解决什么痛点**：很多门店官网是前端渲染的 SPA，AI 爬虫抓到的是一个空 `<div>`——这四个 skill 负责「诊断为什么不可见 → 检查本机修复能力 → 实际改代码（prerender / sitemap / robots.txt / **llms.txt** / 结构化数据）→ 打包成交接文档」。

**限制**：需要能接触到网站源码，纯 OTA 渠道为主的门店用不上；也是海外引擎视角。
